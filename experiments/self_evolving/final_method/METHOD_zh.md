# 方法文档：文档驱动时间序列预测的三角色自进化（最新版本）

更新时间：2026-09-27（扩充 dictionary 版） · 数据：Dr-CiK（训练 80 / dev 20 / test 99）· 基础预测库：原有 31 个方法（Toto-2.0、Chronos-Bolt、PatchTST 等深度模型和 AR、ARIMA、Theta、SES、STL-ETS 等统计方法），加上完整的 93 个统计方法组合。93 个里有 48 个能在 Dr-CiK 上产出预测，合计 50 个方法，其中覆盖至少 90% 训练任务的 37 个进入进化

## 1. 一句话概括

系统由 **Numerical、Retrieval、Decision** 三个角色组成。所有可学习的部分都**只用训练集**进化或学习：
- 先由 Numerical 从 37 个方法中**进化出基础预测程序**；
- 再由 Retrieval 从文档中找出"过去的异常"和"未来的事件"；
- Numerical 修复异常历史，Decision 用只看历史的校验决定是否采用；
- 最后三方联合进化出的团队对未来做局部修正。

dev 只在最后打开一次做把关。

## 2. 流水线（按执行顺序）

| 步骤 | 角色 | 做什么 | 怎么得到（进化 / 学习） |
|---|---|---|---|
| ① 基础预测 | Numerical 第一部分 | 用方法预测组合出基础预测：**0.854·Toto + 0.046·ARIMA（自动定阶）+ 0.100·TimesFM-2.5**，**向最后观测值收缩 20%**，没有差分项，不裁剪 | **进化 + agent 精修**：先进化出 0.95·Toto + 0.05·ARIMA（收缩 20%），再由 agent 协同进化加入 10% TimesFM（见 6c）。进化部分：从 37 个单一方法出发，带类型的变异（换方法、改权重、加项或删项、相减修正、收缩、裁剪），用训练集结果打分（变差任务按 3 倍惩罚），30 代 |
| ② 找过去的异常 | Retrieval（抽取） | GPT 读每个任务的全部文档，输出时间线：测量错误、一次性干扰、周期性异常，以及以后还会不会发生，并附原文引用 | **进化**：GPT 作为变异算子改写抽取指令，用训练集的标准证据标注（gt_evidence）算 F1 打分，4 代，F1 从 0.054 到 0.464 |
| ③ 修复历史 | Numerical 第二部分 | 把"不会再发生"的异常段用**同相位中位数**补齐，让 Toto 在修复后的历史上重新预测 | **学习**：补值方法从 4 种（同相位中位数、线性插值、季节 naive、截断）里，按训练集上完整流水线的结果选出 |
| ④ 是否采用修复 | Decision | 把历史最后一段留出来，比较原始历史和修复后历史的回测误差，**降低 30% 以上**才采用；采用时，①里的 Toto 项换成修复后的预测 | **学习**：门槛从 {0, 5%, 10%, 20%, 30%, 不修} 里按训练集结果选出 |
| ⑤ 修正未来 | 三角色团队（nrd4） | 对文档给出的未来修正逐条决定"接受、减半或拒绝"；Toto 越不可靠的地方越相信文档 | **联合进化**：Numerical 的幅度校准器（爬山）、Retrieval 的逐条校验器（进化策略）、Decision 的强度和门槛（变异），组成 32 个团队在训练集分层 fold 上整队打分，失败整轮回滚，15 代 |

## 4. 各部分的进化曲线

- **Numerical 第一部分**（训练集 fitness）：0 → 0.021 → 0.033 → 0.049 → 0.088 → **0.099**（31 个方法时最高是 0.093）
- **Retrieval 抽取指令**（证据 F1）：0.054 → 0.206 → 0.276 → 0.292 → **0.464**；全量训练集召回从 5% 升到 48%，准确率从 9% 升到 67%
- **三角色联合进化**（seed 1 的团队 fitness）：0 → 0.071 → 0.075 → 0.081 →（第 4 到 14 代回滚）→ **0.082**；Retrieval 校验器的逐条收益从 3.25 升到 7.59
- 逐代的详细记录见 `EVOLUTION_LOG.md`。

## 5. 学到的规则（可解释）

- **基础预测**：进化自己选出 Toto 作为主体，再加少量自动定阶 ARIMA，并向最后观测值收缩，用来防止极端误差。新加入的统计方法没有进入最优程序，只出现在其他候选里（例如贝叶斯在线变点预测、简单移动平均）。
- **逐条修正校验器**：接受"有事件类文档支撑的大修正"，拒绝"来自说明类或方法论文档"的修正（该特征权重 −2.4 到 −3.7）；Toto 越不可靠的地方越相信文档。
- **抽取指令**（GPT 自己总结出的规则）：
  - 其他实体的事件只有明确关联到目标时才采用；
  - 区分测量错误和真实而持久的变化；
  - 保留"本周不再发生"和"以后都不会发生"之间的范围差别；
  - 不插值猜测时间边界。
- **修复门槛**：训练集选出的是较严格的 30%，也就是只采用把握很大的修复。

## 6. 数据使用和限制

- 所有进化和学习都只用训练集。dev 在最后打开一次（两个指标都变好，通过）；标准证据标注只在训练集使用。
- **test 之前已经打开过多次，所以 test 数字都是探索性的**，不能用来在方法之间做选择。
- 第一部分的惩罚系数（3）是在看过惩罚系数 0.5 那一版的 dev 和 test 之后才定的，有轻微污染。
- 第一部分的"向最后观测值收缩"作用在所有任务上：对少数误差很大的任务帮助很大，对多数任务是轻微变差，所以 test 上约 35 个任务变差。"以 Toto 为固定基础"的版本几乎不伤害，可以作为对照。
- **目前仍是人工固定的部分**：
  - 抽取格式（5 种区间类型）；
  - ⑤ 使用的文档修正（一次性抽好的旧 cards）。

## 6b. 补全 5 个基础模型和 5 个组合方法（对照实验）

portfolio 里除了 93 个统计方法，还有 5 个基础模型（Toto-2.0、Chronos-Bolt、TimesFM-2.5、Moirai-2.0、Granite-TTM）和 5 个组合方法。每个组合方法是"一个基础模型 + 一个统计方法"，组合方式是加权平均，或按信号切换。
- 3 个新模型用仓库自己的适配代码跑：`scripts/timesfm_full.py`、`scripts/tsfm_full.py`。组合方法用仓库自己的组合代码算：`scripts/combined_full.py`。
- 覆盖：TimesFM 和 Moirai 覆盖全部 199 个任务。Granite-TTM 只支持小时、天、周频率，而且最多预测 96 步，所以只覆盖 126 个。第一部分现在从 **43 个方法**里选。

单个方法（sMAE / sRMSE）：

| 方法 | 训练集 | dev | test（只看，不用来选） |
|---|---|---|---|
| Toto-2.0 | 0.3884 / 0.6018 | 0.3921 / 0.5871 | 0.3814 / 0.5903 |
| TimesFM-2.5 | 0.3567 / 0.5637（80 个任务里 51 个比 Toto 差） | 0.3106 / 0.4502 | 0.3829 / 0.6094 |
| TimesFM + 季节 naive（组合） | 0.3560 / 0.5654 | 0.3008 / 0.4506 | 0.3796 / 0.5966 |

**不以 Toto 为参照的 fitness**（`scripts/num_part1_rel.py`）：
- 每个任务以"所有单一方法误差的中位数"为参照，算相对收益，并截断到 [−1, 1]，这样少数误差特别大的任务不会主导结果。
- 3 种设置（惩罚 0 或 0.5，最多 2 项或 4 项）进化出的最优程序都是 **约 0.9·Toto + 0.1·ARIMA，向最后观测值收缩约 10%**。
- 训练集内部交叉验证三折 held-out 的 sMAE 都变好：+13.5%、+10.9%、+5.8%。
- 如果仍以 Toto 为参照、但去掉惩罚，进化会选 TimesFM 类的程序。这时训练集误差很低，dev 反而变差（0.3963 / 0.5453），属于过拟合。

**结论**：
- 就算 Toto 在 fitness 里没有任何特殊地位，训练数据本身也会选 Toto，所以"从 Toto 出发所以肯定比 Toto 好"这个担心可以排除。
- TimesFM 在 dev 上的优势，在训练集和 test 上都不成立。
- 用新的第一部分跑完整流水线，dev 是 0.3415 / 0.5106，比主方法（0.3380 / 0.5064）略差，**主方法保持不变**。
- 各设置的完整结果见 README 和 `artifacts/dictionary_expansion/`。

## 6c. 统一端到端打分和 agent 协同进化（2026-09-28）

**起因**：各部分用各自的指标进化，改好一部分不一定让最终预测变好。例如抽取指令用全部 80 个训练任务再进化，证据 F1 从 0.477 升到 0.553，但重跑流水线后预测反而变差（dev 0.3477 / 0.5180）。

**第 1 步：统一端到端打分 + 三角色轮流进化**（`scripts/coevolution/e2e.py`、`coevo.py`）
- 任何角色改了，都用整条流水线在训练集上的最终误差来决定接受还是回滚。
- 嵌套交叉验证：训练集上越来越好，但留出 fold **三折都变差**：+0.247 → +0.215，+0.172 → +0.132，+0.338 → +0.201。收紧接受规则后是 +0.226、+0.145、+0.295，仍然变差。
- 结论：在主方法附近做随机搜索，会过拟合 80 个训练任务。

**第 2 步：agent 提议者 + 隐藏 fold**（CORAL / Meta-Harness 式，`scripts/coevolution/` 下的 `evald.py`、`submit.py`、`run_agent.py`、`TASK.md`）
- **评估器隔离**：Codex agent（gpt-6-sol）可以改配置的任何部分，但不能自己跑评估。它们把配置提交到队列，由单独的评估进程打分：
  - 返回 2 个可见 fold 的分数和逐任务结果；
  - 第 3 个 fold 隐藏，只返回"通过或不通过"；
  - 可见分数变好、并且隐藏 fold 不变差，才成为新的最好配置。
- **共享记忆和提醒**：共享所有尝试、笔记、脚本，以及可见任务的完整数据。每轮提醒记笔记，每隔一轮提醒整理，没进步就提醒换方向。
- **对照**：A 组 3 个 agent 共享记忆，B 组 3 个 agent 各自独立。预算都是每人 20 次提交，实际每人用了 5 到 14 次。
- **拦截情况**：有 17 次提交在可见 fold 上变好，但被隐藏 fold 拦下。
- **被接受的改动**：
  - A 组：基础预测里加入 3%，再加到 5% 的 Moirai；
  - B 组：加入 **10% 的 TimesFM-2.5**。
  - 抽取、校验器、决策参数的改动都没通过。
- **结果**（dev 只在最后看一次；test 是 seed 1）：
  - 主方法：dev 0.3380 / 0.5064，test 0.3251 / 0.5061
  - A 组：dev 0.3354 / 0.5014，test 0.3244 / 0.5035
  - B 组：**dev 0.3285 / 0.4885，test 0.3223 / 0.4982**
  - B 组用 3 个 seed 确认稳定后，采用为新的主方法。
- 这次共享记忆没有胜过最好的独立 agent。每组只有 3 个 agent，样本小，不能下定论。
- **核查**：没有 agent 读取 dev、test 或隐藏 fold 的标签文件。有一个 A 组 agent 在第 3 轮读了评估器的状态文件，里面有隐藏 fold 的汇总分数，但没有逐任务标签。它被接受的改动都在第 2 轮，也就是读这个文件之前。
- 所有 agent 的笔记、脚本、提交记录和最好配置：`artifacts/coevolution/`。
