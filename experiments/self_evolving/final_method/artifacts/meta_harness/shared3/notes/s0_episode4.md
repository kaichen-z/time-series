# s0 episode 4: document duration corrects extracted window endpoints

Read all shared notes, the current best harness, the 80 unlabeled Train views, and only the permitted 54 visible traces. The prior best had no visible task on which its adjustment worsened raw MAE+RMSE relative to the base. The clearest remaining correctable errors were at event-window boundaries, not correction magnitudes.

Several hourly documents explicitly describe a sixty-minute event, but their positive correction covers two hourly bins. In visible tasks 129, 134, 135, and 140, the observed spike is in the first bin, while the second returns to baseline. A narrow rule truncates only positive two-bin hourly corrections to one bin when the document text explicitly contains a one-hour duration phrase. It also changes unlabeled Train tasks 130 and 139. Submission `s0_033953_b09a64` passed the hidden check and raised visible fitness from 0.2611 to 0.3021. All 80 Train views returned H finite floats. The four visible cases represent two underlying series, so independent support is limited.

Visible tasks 104 and 87 have a zero-multiplier correction across five daily bins, although their documents say the ATM outage lasted four days / 96 hours. The truth rebounds in the fifth bin. Truncating only zero-valued five-bin daily corrections with explicit four-day text improved both. Submission `s0_034339_cdcddb` passed the hidden check and raised visible fitness to 0.3055. Only those two visible tasks changed from the previous harness. They share the same underlying series and truth.

Both rules are now in `shared/best_harness.py`. They preserve the existing validator and correction strengths; they only correct a one-bin endpoint error where explicit document duration supports it. Two of five episode submissions were used. Do not generalize to other durations or broader timing inference without evidence; phrase matches may refer to a distractor event in these long document collections.
