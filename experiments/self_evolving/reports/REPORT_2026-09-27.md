# Self-evolving Numerical / Retrieval / Decision on Dr-CiK and Time-MMD: full experiment report

Date: 2026-09-26/27. Code: `.scratch/self_evolving/` in the time-series repo.
All metrics are relative improvements over Toto-2.0-22m (positive = better): sMAE, sRMSE, and the joint
error sMAE+sRMSE (Dr-CiK point metrics, cap 5). W/R = number of tasks improved / worsened.

## 0. Protocol and data-use record

| Item | Setting |
|---|---|
| Dr-CiK split | `splits/drcik_public_80_20_99_v3.json`: train 80 / dev 20 / public_test 99 (synthetic tasks). 80 more "human" tasks exist, but their labels are hidden and were never used |
| Time-MMD split | 894 tasks: train 531 (477 after removing 54 with non-finite values) / dev 181 / test 182 |
| Base model | Toto-2.0-22m. Cached forecasts; Toto hindcasts on truncated histories match the cached forecasts to 5e-7 relative error |
| Selection | Everything is chosen on train only. Main estimate = nested stratified cross-validation on train: 3 outer folds, every group spread over folds, the same way train and test are split. We first used leave-group-out CV, but it was too strict: even the hand-designed method is negative under it, while 95% of test groups also appear in train |
| Dev gate | Dev is opened once per final method; it passes only if neither sMAE nor sRMSE gets worse; otherwise the method falls back to Toto |
| Test | Dr-CiK public_test was first opened for nrd3 (9/26 15:50Z). Every later test number is **exploratory**. It was reopened several times at the owner's request, so test numbers must not be used to choose between methods |
| Document labels | Document `role`/`subtype` labels are never shown to any model. `annotations.gt_evidence` is used **only on train**, as Retrieval's evolution signal (tl2) |

## 4. What is actually evolved in the main method (nrd4, final teams on all of train)

**Numerical**
- Magnitude calibrator: evolved; it ends ≈ the initial setting `{win: all, deseason: false, ref: median, stat: q90, mult ≈ 1.0–1.03}`.
- Toto trust profile, i.e. median Toto hindcast error per cell (fixed statistic): day|flat 1.81, day|seas 0.16, hour|seas 0.87, hour|flat 0.51, minute|seas 0.22, minute|flat 0.58, second|flat 1.21.

**Retrieval** (per-correction validator; weights for seeds 1/2/3):

| Feature | Seed 1 | Seed 2 | Seed 3 |
|---|---|---|---|
| absmag | +3.25 | +1.49 | +3.87 |
| conf | −0.07 | +0.58 | −1.18 |
| wfrac | +0.63 | +0.66 | +1.07 |
| docbase | **−2.77** | **−2.38** | **−3.72** |
| ratio | ≈0 | ≈0 | ≈0 |
| trust | +1.02 | +0.34 | +0.77 |
| bias | −2.75 | −1.55 | −1.75 |

The learned rule is: accept large corrections backed by event-type documents, reject descriptive/methodology documents, and trust documents more where Toto is less reliable.

**Decision:** strength 1.0, trust gate 0 ~ 0.07.

**tl2 evolved Retrieval instructions** (generation 4, full text in `tl2_best.json`). Key rules GPT learned from train feedback:
- prioritise direct target statements and explicit assumptions over logs/reports;
- apply another entity's event only when explicitly linked;
- separate measurement errors from real lasting changes, and keep the exact scope of "not again this week / not in the future";
- use recurring_pattern only when repetition is stated or shown;
- never interpolate boundaries; quote complete evidence.

## 5. Conclusions

1. **Main result (strict protocol): nrd4.**
   - Train CV +6.4% vs the hand-designed method's +4.6%; dev passes 3/3.
   - Test (exploratory): sMAE +3.5%, sRMSE +6.2%, about 30 better / 1–2 worse. This is still below the hand-designed method on test.
2. **Numerical's contribution.**
   - Blending in dictionary methods causes most regressions: turning it off takes CV from +2.0% to +5.5% and harmed tasks from 45 to 19.
   - As judgement features, Numerical's signals help: +2.7% → +6.4%. Almost all of that comes from the cell trust profile; the evolved calibrator barely moves.
   - The two-stage dictionary → co-evolution version (nrd11) uses the dictionary features but performs the same as nrd4.
3. **Stronger search overfits at 80 train tasks.** GEPA-style Pareto selection + islands raises train CV to +8.1% (9/9 folds), but fails dev and does worse than nrd4 on test.
4. **The bottleneck is document extraction, not selection.** The biggest new lever is **history repair**: Dr-CiK documents often say that a past period was abnormal and will not recur. Retrieval evolved with gt_evidence recovers this much better (F1 0.04 → 0.48).
   - Repair alone gives the highest test sMAE of any method (+11.7%, exploratory).
   - It is **not stable yet**: dev −3.8%, test 10 better / 13 worse. The failures are natural daily cycles labelled as anomalies, and a weak imputation method.
5. **Next steps:**
   - history-only hindcast validation of each repair (Decision);
   - evolve the imputation method (Numerical);
   - add a natural-cycle constraint to the extraction instructions;
   - then combine history repair with nrd4's future corrections;
   - judge only on train CV + dev, and use the hidden-label Dr-CiK split, if officially available, as a clean final test.
