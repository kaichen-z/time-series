# 汇报讲稿：文档驱动的时间序列预测 · 三角色自进化

（建议 12 到 15 分钟。每节开头的【】是可以直接放在幻灯片上的要点，其余是讲的内容。）

---

## 1. 问题和设定（1 分钟）

【强基础模型 + 文档 → 能不能自动学会"什么时候、怎么修正"】

我们的出发点是：Toto 这样的时间序列基础模型只看数值历史，已经很强；但很多任务的文档里还有额外信息，比如"下周节假日""传感器曾经故障""以后不再维护"。问题是：能不能让系统**自己进化出**"从文档里提取什么、怎么改 Toto、什么时候不改"，而不是靠人手工设计规则。

系统分三个角色：
- **Numerical**：只看数值历史。
- **Retrieval**：只看文档，产出证据或修正。
- **Decision**：只能在已有候选里选择，或者退回 Toto，自己不生成预测。

第 0 代严格等于 Toto，所有进化都从"什么都不改"出发。

数据：
- **Dr-CiK**：训练 80 / dev 20 / test 99。
- **Time-MMD**：训练 477 / dev 181 / test 182。

指标：sMAE、sRMSE，越小越好。Toto 在 Dr-CiK test 上是 **sMAE 0.3814、sRMSE 0.5903**。

## 2. 评估协议（1 分钟）

【只在训练集上进化；dev 只开一次把关；test 只作最终报告】

- **进化和选择只用训练集**。主要估计方式是训练集上的嵌套交叉验证，按领域分层，和 train/test 的切分方式一致。
- **dev 把关**：sMAE 和 sRMSE 都不能变差，否则退回 Toto。
- **文档的角色标签**（哪篇是干扰文档）从不给模型；**标准证据标注**只在训练集上当作进化信号。
- 需要如实说明：test 从 nrd3 开始打开过多次，后面的 test 数字都属于**探索性**。

## 3. 版本演变（4 分钟）

【五个阶段：让三方能进化 → Numerical 只做判断 → 改进修正来源 → 更强的进化方式 → 发现文档的真正用法】

**阶段一：从选方法到进化 dictionary**
- v1/v2：Numerical 只能从 31 个现成方法里挑。训练 CV 的联合误差停在 Toto 的 0.990 附近。原因是从 Toto 出发，单步改动迈不出第一步。
- nrd3：Numerical **自己进化 dictionary**，Decision 把 dictionary 方法混进 Toto。训练 CV 0.990 → 0.940，但 test 上 **38 个任务变好、18 个变差**，dev 只有 1/3 个 seed 通过。
- 诊断：关掉"混合"后，训练 CV 从 +2.0% 升到 +5.5%，变差任务从 45 个降到 19 个。**混合是变差的主要来源**。

**阶段二：Numerical 不再替代 Toto，只提供判断（nrd4，主结果）**
- Numerical 输出两类只看历史的判断：序列的正常波动幅度，以及 Toto 在这类序列上的可信度。这些判断作为特征交给 Retrieval 的逐条校验器；Decision 只剩 2 个参数。
- 结果：
  - 训练 CV 0.990 → **0.927**；
  - dev 3/3 通过（0.9792 → 0.9786）；
  - test sMAE 0.3814 → **0.3681**、sRMSE 0.5903 → **0.5539**，约 **30 个变好、1 到 2 个变差**。
- 消融：去掉 Numerical 的判断，训练 CV 只有 0.964。

**阶段三：想让修正本身更准（nrd5 到 nrd10）**
- 让 GPT 进化抽取指令、用残差模型加 conformal 保证、要求证据核对并让 3 个模型投票、统一窗口变换、按精确时间重新抽取、合并两套抽取。
- 共同结论：训练集上都能拿到一些提升，但 test 都没超过 nrd4。
- 关键诊断：训练集 75 条文档修正里只有 29 条有用（39%）。有害的 46 条里：
  - 26 条是时间窗口不对；
  - 13 条是方向错了；
  - 7 条是幅度太大。
- 也就是说，**问题出在抽取本身，而不是筛选**。

**阶段四：更强的进化方式（nrd11、nrd12）**
- nrd11：先让 dictionary 进化，再把它变成判断特征参与联合进化。dictionary 特征确实被用上了，效果和 nrd4 持平。
- nrd12：参考 GEPA 的 Pareto 选择加 FunSearch 的岛屿模型。训练 CV 最好（0.911，9/9 个 fold 为正），但 dev 1.0255、1.0286，没有通过；test 也不如 nrd4。
- 结论：只有 80 个训练任务时，**搜索越强越容易过拟合**，dev 把关是必要的。

**阶段五：找到文档的真正用法，也就是历史修复（tl、tl2）**
- 发现 Dr-CiK 的文档大量在讲"过去某段数据是异常的、以后不会再有"。Toto 会把这些异常当成规律学进去。
- 把这些异常段从历史里修掉，再让 Toto 重新预测：test sMAE 0.3814 → **0.3369**（改善 11.7%），是所有方法里最高的。
- 但还不稳：dev 0.9792 → 1.0166，test 上 10 个变好、13 个变差。

## 4. 重点一：tl2 是怎么做的（2.5 分钟）

【Retrieval 抽取状态时间线 → Numerical 修复历史 → Toto 重新预测；抽取指令用标准证据进化】

**第一步，Retrieval 抽取时间线。** GPT 读一个任务的全部 70 多篇文档，输出一组区间，每个区间包括：
- 类型，共 5 种：测量错误、一次性干扰、周期性模式、状态、未来事件；
- 起止时间，以及是否按天或按周重复（例如"每天 08:00 到 14:00"）；
- 以后是否还会发生；
- 影响方向；
- **原文引用**。

**第二步，Numerical 修复历史。** 对"以后不会再发生"的测量错误、一次性干扰和周期性异常：
1. 把对应的历史时间步用同相位的中位数补齐；
2. 再让 Toto 在修复后的历史上重新预测。

幅度完全来自历史本身，不需要 LLM 猜，也没有需要拟合的参数。

**第三步，抽取指令怎么进化。**
- **fitness**：在 30 个训练任务的小批量上，计算抽取结果和标准证据标注的 **F1**：
  - 召回：标准证据里带时间或"以后是否发生"信息的那些，被抽到了多少；
  - 准确率：抽出来的引用中，有多少真是证据，而不是干扰文档。
- **变异算子**：GPT-6-sol。把当前指令，以及训练集上的具体反馈（漏掉的标准证据原文、误抽的干扰原文）交给它，让它改写指令。
- **选择**：每代 2 个子代，比当前更好才接受，否则保留原指令。共 4 代。

**结果：**
- 进化曲线 F1：0.054 → 0.206 → 0.276 → 0.292 → **0.464**。
- 全量训练集：召回 5.4% → **48.3%**，准确率 9.1% → **67.0%**。
- GPT 自己学到的规则，例如：
  - "其他实体的事件只有明确关联时才采用"；
  - "区分测量错误和真实而持久的变化"；
  - "保留'本周不再发生'和'以后都不会发生'的范围差别"；
  - "不插值猜测边界"。
- 修复效果：训练集联合误差 0.990 → 0.835（改善 15.7%）；test sMAE 0.3814 → 0.3369。

**下一步要解决的**：dev 上的失败主要有两类。一类是把自然的日周期当成异常（太阳辐照度的夜间为 0），另一类是补值方法不适合噪声大的序列。计划让 Decision 用"只看历史的回测"来判断是否接受每一次修复，并把补值方法作为 Numerical 的进化对象。

## 5. 重点二：dictionary 是怎么 self-evolve 的（2 分钟）

【可执行程序 + 类型化变异 + 只看历史的回测 + MAP-Elites】

**个体**：每个 dictionary 成员是一个可执行的预测程序，用"积木"组合而成：
- **基础算子**：naive、季节 naive、漂移、SES、阻尼趋势、Theta、滑窗均值、滑窗线性回归、季节轮廓，各自带参数（平滑系数、窗口长度、周期数等）；
- **组合算子**：两个程序加权**混合**；按季节性强弱**路由**到不同程序；把预测**裁剪**到历史范围附近。
- 每个程序最多 5 个节点，大小有惩罚，防止无限变复杂。

**变异算子（带类型）**：调参数、换一个新的基础算子、和另一个成员混合、加路由、加或改裁剪、拆掉一层组合。

**fitness 只看历史，不碰标签**：在每个训练任务的历史内部做滚动回测，把历史的最后 H 个点和再往前 H 个点留出来预测，计算误差，再**减去 Toto 在同样位置的回测误差**。也就是说，fitness 衡量的是"比 Toto 好多少"。

**MAP-Elites**：按"频率（秒 / 分钟 / 小时 / 天）× 是否有明显季节性"分格，每格只保留回测最好的程序。所有格子的精英就是 dictionary。每一代从现有精英里抽父代、产生子代，子代在某一格更好就替换那一格。

**结果**：
- 精英和 Toto 的回测联合误差之差（各格平均）从第 0 代的 **+0.092（比 Toto 差）**进化到 **-0.05 到 -0.07（比 Toto 好）**，最终 6 个精英程序；
- 例如在"小时 × 季节性"的格子里，精英的回测联合误差比 Toto 低约 0.29。

**怎么用**（这是踩过坑之后的结论）：
- 直接和 Toto 混合，会导致大量任务变差（nrd3）；
- 现在（nrd11）是把"这个格子或任务里 dictionary 比 Toto 好多少"作为判断特征交给联合进化。它的权重在 9 个 fold 里都是正的：dictionary 越优于 Toto 的地方，系统越愿意相信文本修正。

## 6. 重点三：3-agent 是怎么 co-evolve 的（2 分钟）

【三方各自进化 → 组成团队 → 在训练 fold 上整队打分 → 更好才接受，否则整轮回滚】

每一代（共 15 代）：
1. **Numerical 自己进化**：幅度校准器爬山 3 小代、每代 12 个子代，fitness 是只看历史的"预测下一段波动幅度的准确度"；同时更新按格子的 Toto 可信度画像；两阶段版本还包括 dictionary 的特征。
2. **Retrieval 自己进化**：逐条修正校验器是一个低自由度的打分器，特征包括修正幅度、置信度、窗口长度、是否为说明类文档、幅度与历史波动之比、Toto 可信度。输出"接受 / 减半 / 拒绝"。用进化策略（种群 16、精英 4、15 小代）优化**逐条修正收益**，有害修正按 1.5 倍惩罚。
3. **Decision 出变体**：只有 2 个参数，修正强度和可信度门槛，每代出 6 个变体。
4. **联合选择**：从三方的当前版本和新变体里随机组成 32 个团队，在训练集的分层 fold 上整队打分：
   - 每个 fold 的得分 = 平均收益 + 0.5 × 平均"负收益"（专门惩罚变差的任务）；
   - 团队 fitness = 各 fold 得分的平均 − 0.25 × fold 间的标准差（奖励稳定）；
   - **比当前团队更好才接受，否则整轮回滚**。

**为什么要联合选择，而不是各自最优**：三方是互相依赖的。例如 Retrieval 的校验器要用 Numerical 给的可信度特征；某个校验器只有在 Decision 的某个强度下才好用。只在团队层面打分，留下的才是互相配合最好的组合。

**最终学到的规则**（nrd4，可解释）：
- 校验器对"说明类文档比例"的权重是**强负**（−2.4 到 −3.7），对"修正幅度"是正（+1.5 到 +3.9），对"Toto 不可信程度"是正（+0.3 到 +1.0）；
- 翻译成一句话：**只接受有事件类文档支撑的大修正，拒绝来自说明类或方法论文档的修正；Toto 越不可靠的地方，越相信文档。**
- 训练集上 75 条修正只接受了 23 条，其中 18 条（78%）是有用的。

## 7. 结论（1 分钟）

【nrd4 是稳定的主结果；历史修复是上限最高的新方向；Time-MMD 是"文本弱"的边界】

1. 按严格协议，**nrd4 是主结果**：test sMAE 0.3814 → 0.3681、sRMSE 0.5903 → 0.5539，几乎不伤害（约 30 个变好、1 到 2 个变差）。
2. **Numerical 的正确角色是"判断"而不是"替代"**：去掉它的判断，训练 CV 从 0.927 退到 0.964。
3. **小数据上，强搜索会过拟合**：nrd12 训练 CV 最好，但 dev 和 test 更差，所以 dev 把关必不可少。
4. **文档最有价值的用法是修复历史**：tl2 的 test sMAE 达到 0.3369，是所有方法里最好的；下一步要把"该不该修"做稳，再和 nrd4 的未来修正叠加。
5. **Time-MMD**：文档几乎没有前瞻信息，所有方法都接近 0。系统正确地学会了不改 Toto，这是一个诚实的边界结果。

## 8. 可能被问到的问题

- **"test 看了很多次，结果可信吗？"** 主结果 nrd4 是按训练 CV + dev 选出来的，没有用 test 选；其他版本的 test 数字只作分析参考。最干净的最终测试，是 Dr-CiK 另外 80 个标签隐藏的任务（需要官方评测）。
- **"用 gt_evidence 算不算泄露？"** 它只在训练集上作为进化信号，和训练集的真实值同等对待；dev 和 test 上完全不用。
- **"和 CompEvo 等工作的区别？"** 我们进化的是可执行、可审计的程序（dictionary 程序、校验器、抽取指令）；Decision 只能在已有候选里选或者退回 Toto；有整轮回滚和 dev 把关，以及明确的"不伤害"目标。
