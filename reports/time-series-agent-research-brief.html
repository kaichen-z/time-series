01 / PAPERS

Four Papers, Four Complementary Modules

They cannot simply be plugged together, but each contributes a key idea for forecasting, belief updating, long-horizon collaboration, or controlled retrieval evaluation.

FORECASTER

Nexus

Contextualization → macro/micro outlook → forecast synthesis. Reuse: the multi-resolution forecaster.

Limitation: assumes context is already retrieved — no search over a noisy corpus.

arXiv 2605.14389 ↗
BELIEF LOOP

BLF

Tracks probabilities and open questions across an iterative tool-use loop. Reuse: the belief state and stopping criteria.

Limitation: built for binary-event probabilities, not continuous series.

arXiv 2604.18576 ↗
EVOLUTION

CORAL

Long-running agents share memory via notes and skills, with heartbeat reflection. Reuse: dev-set strategy evolution.

Limitation: not a forecaster — no test-time feedback from forecast error.

arXiv 2604.01658 ↗
BENCHMARK

Dr-CiK

Forecast-useful evidence retrieval from a noisy corpus. Reuse: the data, labels, and three-level evaluation.

Limitation: “one DR pass → one forecast” — no forecast-feedback loop.

arXiv 2605.27904 ↗
How they fit: Dr-CiK supplies the task and evaluation; Nexus supplies the downstream forecaster; BLF supplies structured iteration; CORAL is better suited to later-stage outer-loop optimization on the development set.

Not a Keyword-Matching Problem

Confounder · profile mismatch · temporal misalignment · series misinterpretation · noisy context — plausible-sounding but wrong in entity, time, or trend.

Needs time-series-grounded verification, not embedding similarity alone.

Dr-CiK evaluates “finding evidence” separately from “forecasting with evidence,” so every failure is not automatically blamed on the forecaster.

WHAT sCRPS MEASURES

Distributional Accuracy, Not a Single Point

CRPS = mean |sample − truth| − 0.5 × mean pairwise sample distance

Lower is better. Rewards accuracy without letting a model “cover the answer” via an arbitrarily wide distribution.

Key observation: Correct evidence substantially improves forecasts — but most DR agents retrieve low-coverage, high-distractor evidence that can make a forecaster worse than with no context at all.
05 / GAP

The Actual Research Gap

Current systems optimize semantic relevance. Time-series forecasting requires optimizing actual value for the target variable, forecast horizon, and predictive distribution.

Current Pipeline

A DR agent may search repeatedly internally, but it emits evidence only once. After forecasting, uncertainty and evidence gaps are not fed back to retrieval.

Research once → Forecast once
The retrieval objective should shift from “Is this document topically relevant?” to “Can this information change or improve the forecast?”

Gap 01 · Grounding

Agents rarely cross-check a document against the observed history, so time-series distractors slip through.

Gap 02 · Feedback

An uncertain forecaster can't ask retrieval to go find the specific evidence it's missing.

Gap 03 · Efficiency

More agents and searches add noise and latency without explicit budgets and stopping rules.

06 / METHOD
Proposed method

Forecast-Aware Iterative Retrieval

The goal is not unconstrained agent “imagination,” but testable future hypotheses. Only evidence that passes entity, temporal, variable, and numerical consistency checks can enter the final forecast.

STEP 01

Diagnose

Read trend, seasonality, anomalies, and regime changes in the target series.

STEP 02

Retrieve

Search around information gaps and competing hypotheses — not generic topic search.

STEP 03

Verify

Check entity, event time, effect window, and consistency with the observed series.

STEP 04

Forecast

Turn structured evidence into trajectories with calibrated uncertainty.

Uncertainty / evidence conflict / missing horizon → new information gap → another retrieval round

Diagnosis Agent

Reads the numerical signal and tells the retriever what needs explaining.

Verifier

Programmatic checks on dates/entities, an LLM on causal chains, a numerical check against the historical trajectory.

Hypothesis Evolution

Hold candidate scenarios (seasonality, shock, regime shift) as hypotheses — retrieve to support or reject, not assume.

Right Variable

Combine mechanism, temporal alignment, and backtesting to check an external variable actually adds signal.

Latency × 2

Model event-to-effect lag separately from retrieval's own inference latency.

Structured Belief

Claims carry provenance, confidence, direction, and time window — caps unbounded context growth.

07 / PLAN

Incremental Experiments, One Component at a Time

First fix the forecaster to isolate the contribution of retrieval. Introduce one mechanism at a time, then evaluate retrieval quality, forecast quality, and efficiency.

Phase 0 · Baseline

Run the Dr-CiK Public Dev Set

No Context, Oracle, Supporting Docs, One-shot Retrieval — validates the data interface and official metrics.

Phase 1 · Forecaster

Adapt Nexus as the Forecaster

Compare to Direct Prompt under identical evidence; sample repeatedly for a predictive distribution.

Phase 2 · Belief Loop

Add BLF-Style Structured Beliefs

Swap binary-probability beliefs for continuous trajectories and evidence slots.

Phase 3 · Verification

Add a Time-Series-Aware Verifier

Measure rejection rates on time-series distractors and wrong-variable evidence.

Phase 4 · Feedback

Forecast Uncertainty Triggers Retrieval

Compare research-once vs. closed-loop on recall, sCRPS, and marginal cost.

Phase 5 · Optional

CORAL-Style Evolution on Dev Data

Improve queries/verifiers on dev only; freeze before the hidden test set.

08 / TEAM

Two Workstreams, One Shared Interface

These are not separate projects. Track A supplies a stable experimental platform; Track B supplies new retrieval outputs; both converge in the same Dr-CiK pipeline.

  • Standardize loaders, context modes, evaluation
  • No Context / Oracle / One-shot baselines
  • Fix a forecaster, then adapt Nexus

TRACK B · RETRIEVAL

Agentic IR Survey & Prototype

  • Survey methods beyond Dr-CiK's five baselines
  • Focus on multi-hop and temporal retrieval
  • Prototype diagnosis + verification
  • Report retrieval quality and runtime cost
Deliverable: history + target + corpus → evidence with citation, direction, window, confidence.
Shared interface: History + Target + Horizon + Corpus → [{ claim, doc_ids, effect_direction, effect_window, confidence }]
09 / NEXT

Decisions Needed Before the Next Sync

Lock down the interface and minimum experiment before increasing the number and complexity of agents.

Which Forecaster Do We Fix?

A reproducible method that samples trajectories and consumes structured evidence — Nexus is an adaptation experiment, not the only option.

Minimum Retrieval Baseline?

One embedding-retrieval pass plus one-shot synthesis, as the reference point for the closed-loop method.

First Core Improvement?

Diagnosis + Evidence Verification — they target Dr-CiK's most visible failure modes directly.

Out of Scope for Now

Action selection; simultaneous Nexus + BLF + CORAL integration; self-evolution using hidden-test ground truth.

Project in one sentence: Study how agents can use time-series patterns and uncertainty to actively retrieve, verify, and organize genuinely forecast-relevant external information — improving future-trajectory predictions while controlling noise, cost, and latency.
