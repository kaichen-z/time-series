同一个定义

每题 MAE、RMSE 都除以真实评分 horizon 的平均绝对量级，再分别 capped at 5.0。(sMAE+sRMSE)/2 只用于确定性排序。

同一个接受门

Child 的 sMAE 与 sRMSE 都不得退化，并且至少一项严格改善；coverage、clipping、crash/invalid 与尾部约束也不能退化。

旧指标不再掌权

MASE、MAE、sMAPE、RMSSE 只出现在明确标记的 diagnostic_only 区域，不参与 active ranking 或 acceptance。

防泄漏边界：runtime 只在 observed history 内切 hindcast window；Train label 只进入 trusted Train evaluator；Dev 只读；Public/hidden 不产生 mutation、Skill 或 Child。
历史结果边界：下方 99 题表格是以前冻结策略在当时 objective 下得到的 legacy experimental evidence。原数字保留不改，也不会被静默当成 schema-v2 active release。当前阶段只完成迁移审计和单题 smoke，不声称新的 benchmark 提升。

0. 现在到底在做什么

本页已有指标仍是历史 Numerical 实验结果。两阶段 Retrieval runtime 与进化协议已经实现，但真实 Retrieval 80/20 LLM 实验尚未启动。

A

Task-conditioned Screening

根据周期、趋势、间歇性、regime、频率、历史长度和 horizon，为每道题生成不同的 Active Dictionary。

已经实现，多版策略已跑
B

Numerical Selection

只用历史回测，在 Active Dictionary 中选择单方法、TSFM portfolio 或受保护的 Combined forecast。

已实现，正在解决尾部风险
C

Context + Decision

Public Harness 已接通 assumption-blind Round 1、带命名 gap 的 provisional Decision、净化后的 Morphology assumptions、可选 Round 2 反证检索与 final Decision。

已实现并通过 fake 测试；真实实验待运行
当前最重要的技术问题：不是候选不够多，而是如何在不看真实 future 的前提下，可靠判断“何时应覆盖强 TSFM baseline”。旧 Selector 在一般任务上有收益，但少数灾难性选择会拖垮平均表现。

1. 研究问题与 Dr-CiK

Dr-CiK 是离线、带上下文的时间序列预测 testbed。每道题已经有历史序列、文档、future values 和 evidence annotations；推理时必须隔离后两者。

我们真正研究的问题

输入：历史数字、频率、forecast horizon；在完整系统中还可有文档。

输出：长度恰好等于 horizon 的点预测；未来可扩展为概率轨迹。

目标：让系统学会针对不同序列选用不同方法，并安全融合数值模型与外部 context。

它不是什么

  • 不是 FutureX 那种等待现实未来发生的 live forecasting。
  • 不是对 LLM 权重做 SFT/RL；目前演化的是 artifact、prompt、policy 和代码。
  • 不是用 Test 标签反复调参；Public Test 只能作为已消费的 regression test。
  • 不是把所有方法平均起来；每个覆盖都必须通过 history-only gate。

3A. 两阶段 Retrieval Self-Evolution

这是已经实现的安全与进化路径，不是已经取得经验性提升的结果。仓库内 v000 release 是未经评测的 seed。截至 2026-08-28，没有真实 Retrieval 80/20 LLM evolution、没有通过接受门的 v000 后续 release，也没有 Retrieval Public Regression 或 hidden 分数。

Round 2 永远看不到 candidate ID、forecast array、hindcast sMAE/sRMSE、source code、future values、ground-truth evidence，也看不到 evaluator-only 的文档 role/subtype。文档、chain 和 citation budget 都在 host verification 与下游使用之前截断。

结果解析后的学习只会写入 candidate Retrieval Skill。内部 mutation Child 可以把某个 candidate ID 写入其期望最终生效的 active_skill_ids；只有该 Child 精确点名的 candidate 才会在精确的内部 Train shadow stage 中，通过真实 two-stage agent 与 verifier 投影。Trusted evaluator 还会在 label 不可见时再次运行 harness，并逐个拿掉已使用的 candidate；它保留 omitted execution 的真实最终候选池，包括其中任何替代 contextual candidate，绝不会从 primary run 合成候选池。继承的 accepted Skill 仍可作为上下文使用；leave-one-out 与 promotion evidence 只针对 Child 实际使用的已点名 candidate ID。完整 screen/fold batch 全部评分后，只有满足至少 3 个任务、2 个 entity、exact-quote validity = 1.0、必要的 leave-one-Skill-out replay、sMAE 与 sRMSE 均不变差且至少一项严格改善、且不增加 catastrophe，才会追加一个带 provenance 的 accepted 版本。仍未 promotion 的已点名 candidate 不能成为 Train winner、进入 Dev 或发布。共享 seed/Parent library 不被 alias；Dev、Public、未知 stage 与 frozen inference 都只解析 active Skill 并保持不变。

认证 checkpoint schema v2 会把规范化 Skill history 与 active origin 写入去重 snapshot table，把每个已完成 evaluation 绑定到精确的 pre/post snapshot hash，并在同一次原子发布中把每个 Genome fingerprint 绑定到其当前 candidate-library snapshot。Resume 会验证 checkpoint digest/epoch、精确 history、active provenance，以及从保留的 with-Skill 与真实 omitted candidate pool 重新计算的 promotion evidence。每个 contextual forecast 还必须在其 source chain 针对不可变 task document 重新验证后，从该 chain 精确重现，且所用 Skill 必须属于独立解析的 Child Genome 所点名 ID。同一任务的所有 replay 必须对同一 primary execution 一致：数值 baseline 的 digest 和得分必须等于 trusted task trace 的 baseline digest 与 coding-oracle metric，最终 primary pool 的 digest 和得分必须等于该 trace 的 contextual-pool digest 与 contextual-oracle metric。之后才能检查 evaluator gate/metric 与 policy 字段不变的精确 candidate-to-accepted copy。认证的有序 completed-batch sequence 会绑定每个 pre-state cache key 与 pre/post snapshot；完整 transition chain 和最终 candidate snapshot 验证通过后，每个匹配记录只消费一次，包括较早未变化的 batch 与较早的 promotion，而不会重复运行。在已认证的 host record 内，缺失、不匹配、语义不一致、来自 Dev、未绑定或重复的状态都会 fail closed；schema v1 checkpoint 不会被静默迁移。

Operator HMAC key 与 trusted host evaluator 是 checkpoint 的信任根。Resume 不会在该 authenticated host record 之外独立证明非确定性 harness execution。持有 key 与当前 external anchor 的 trusted operator 可以有意重新签发或迁移自洽状态；这种管理操作不属于 untrusted-model 和 unauthenticated-tamper 威胁边界。没有当前 operator authority 时，即使是自洽的改写也会被拒绝。创建任何 LLM subprocess 前，key 与 expected-anchor value 都会从环境中删除。

6. JSON、Python 与 Git 的关系

最简洁的理解：JSON 是控制面，Python 是执行面，Git 是继承与审计历史。

Catalog JSON方法是谁、family、assumptions、license、status
→
Manifest / Policycheckpoint、adapter、worker、组合父代、参数
→
Python Runtime真正执行预测、hindcast、筛选和选择
→
Git Generation保存 Parent、Child、diff、commit 与回滚点

JSON 负责什么

  • method_id、family、描述、假设、失败条件、status。
  • TSFM 的 checkpoint/license/adapter 不可变绑定。
  • 训练摘要、revision count、candidate version。
  • 序列化、跨运行恢复、hash 验证。

Python/Git repo 负责什么

  • methods.py 中的 93 个实际预测函数。
  • skills.py 中的九个 history-only primitives。
  • policies.py 中的 TSFM 和 Combined policies。
  • LLM 提交 add / repair / fork / merge / delete，Python 校验，Git 保存 lineage。
Catalog JSON: "sarima_auto 是什么、何时适用、当前状态是什么"
        ↓ identity / routing
methods.py: def sarima_auto(history, horizon, frequency): ...
        ↓ execute + history-only validation
Git commit: Parent → validated Child
        ↓ report
JSON artifact: score、status、revision、hash
所以不是 JSON 和 Git 二选一：同一个方法在 JSON 中有身份证和状态，在 Python 中有可运行实现，在 Git 中有可追溯演化历史。

7. Self-Evolution 到底是什么

这里至少有四个粒度。它们共享 Parent/Child/Train/Dev 逻辑，但“允许改什么”不同。

层级LLM/系统可以改什么产物接受门
Skill learning新增可复用的 numerical/retrieval/decision 经验Skills JSON 或 Python skill训练 outcome validation
Method self-evolutionadd、repair、fork、merge、delete Python forecasting functionsGit-tracked methods.py执行、安全、Train/Dev
Policy/Genome evolutionscreening rules、selector thresholds、prompts、budgets、workflowPolicy JSON/PythonTrain winner → read-only Dev
Source evolutionAgent/Harness Python 与新 orchestration modulesGit patchaudit → tests → Train → Dev

Prompt / Genome / Source 三层 Harness

Prompt

只改一个 Agent 的完整 prompt。表达力最低，最容易审计。

Genome

可共同改变 prompts、candidate budgets、hindcast folds、Retrieval/Decision topology 和 aggregation。

Source

Codex 在隔离 Git worktree 里直接改允许范围内的源码；patch 必须通过静态安全检查和完整测试。

Dictionary 方法的单 Agent 进化

  1. Python 先对 Parent methods 跑历史任务，生成每个方法的 Success / NotApplicable / Crash / Invalid 和误差诊断。
  2. Selector LLM 从失败中选出最值得处理的方法；不是简单删除所有高误差方法。
  3. Coder LLM 生成结构化操作，例如 repair 或 fork。
  4. AST/identity gate 检查方法是否仍保持原算法身份，拒绝“名字叫 SARIMA、实际只 repeat-last”的伪修复。
  5. Child 在少量任务 screen，再在完整 Train 和 read-only Dev 比较。
  6. 只有通过 gate 的 Child 才成为新 Git generation。

8. A 阶段：Task-conditioned Screening

A 阶段不直接决定最终 forecast。它学习“面对这类历史序列，哪些方法值得进入本题候选池”。

从历史数字生成 TaskProfile

History例如非负、很多零、周期候选 24
→
TaskProfileintermittent、trend、regime、length、horizon ratio
→
Applicability Rules每个方法的 OR-of-AND typed predicates
→
Active Dictionarykeep / specialized 留下；repair/quarantine 排除
例：Croston SBA
适用条件：intermittent AND nonnegative

若一条历史序列：
  zero_fraction 很高 → intermittent = true
  全部值 ≥ 0       → nonnegative = true
那么 Croston SBA 进入该题的 Active Dictionary。
这只代表“允许参加 B 阶段”，不代表最终一定选择它。

9. B 阶段：Numerical Selector 与 Combined

B 阶段回答的是：Active Dictionary 已经给定，最终该选谁、是否组合、何时必须退回强 baseline。

每个候选的历史诊断

中心表现

median/recent joint scaled error，以及分开的 median/recent sMAE 与 sRMSE。

稳定性

worst fold、MAD、bias、slope error、phase error、explosion。

可执行性

成功 folds、coverage、Crash/Invalid、NotApplicable、fallback。

Combined 在本项目里的准确含义

当前 Combined 是 forecast-level combination，不是 TSFM 参数相加或 checkpoint merge。

Weighted blend:
  forecast = w × TSFM + (1 - w) × Statistical

Clipped residual correction:
  forecast = TSFM + α × clip(Statistical - TSFM)

Route:
  若历史画像满足条件 → Statistical，否则 → TSFM

Safe Anchor / baseline protection

默认先保留 Toto 或 TimesFM。challenger 只有在历史 folds 上同时满足以下条件才可覆盖：

  • sMAE 与 sRMSE 都不退化，并且至少一项达到严格改善；
  • 至少赢规定数量的 folds；
  • recent fold 和 worst fold 的 regret 都受限；
  • 没有 explosion、coverage 缺失或 catastrophic pattern；
  • Statistical 与 TSFM 预测有足够 diversity，避免无意义重复组合。
核心原则：不是“平均回测分高就替换”，而是“中心表现更好，并且没有任何明显危险的历史证据，才允许替换”。

10. 现在使用哪些指标

正式 Selector gate 已对齐 Dr-CiK point-forecast appendix：sMAE 与 sRMSE 为主；MASE、RMSSE、MAE、sMAPE 用作诊断。

Metric直观解释优点当前角色
sMAEMAE ÷ 真实 future 的平均绝对量级；每题 capped at 5跨量纲、与 Dr-CiK point table 对齐主指标，越低越好
sRMSERMSE ÷ 相同 future scale；每题 capped at 5更惩罚大错误，控制尾部硬安全 gate
MASEMAE ÷ 历史 naive one-step 误差判断是否优于 naive；对零值比 sMAPE 稳健诊断，不再单独决定继承
RMSSERMSE 的 naive-scaled 版本量纲公平、强调大错误诊断
MAE未来每步绝对误差平均直观同任务比较与案例分析
sMAPE相对真实值与预测值平均量级的百分比误差易读接近零时会失真，仅辅助
sCRPS概率预测分布与真值之间的距离同时评价 calibration 与 sharpness当前点预测阶段不算

13. 最新 R1/R2/R3 试验

这是当前正在试的安全升级。它们不是任意搜索组合，而是三层越来越有表达力、同时都保留 Parent fallback 的 challenger。

R1

Single TSFM

从其他 TSFM 中寻找单一 challenger。所有历史 folds 同时通过 sMAE/sRMSE 与 regret gate 才覆盖 Parent。

R2

Multi-TSFM Portfolio

在多个可靠 TSFM 之间做保守组合；portfolio 必须比当前 Parent 更稳定，而不是只比某个弱成员好。

R3

Joint Residual

先得到 R2 的安全 TSFM anchor，再加入 5%/10%/20% 的 task-conditioned Statistical residual correction，并限制 correction scale。

14. 现在真正的问题

已经解决

  • 方法目录不再只是 prompt：93 个真实 Python methods。
  • JSON / manifest / checkpoint / license 的确定性绑定。
  • Train/Dev/Test 和 future-label firewall。
  • NotApplicable 与 Crash/Invalid 分开，不再错误淘汰 specialist。
  • Task-conditioned Active Dictionary 已能产生多个不同子集。
  • sMAE/sRMSE 双指标与 tail diagnostics。
  • Parent fallback 与 Combined baseline protection。

尚未解决

  • 筛选的 task differentiation 仍偏弱，共同核心过大。
  • 历史 hindcast 对未来 regime shift 的迁移不可靠。
  • Combined 在严格 gate 下几乎从不激活；放松又容易产生灾难。
  • 五个 TSFM 的当前本地 worker 环境没有全部恢复。
  • 99 Public Test 已被消费，不能继续用它选版本。
  • Retrieval CLI 尚未接入真实 Numerical/Morphology assumption provider，正式 Retrieval 80/20 实验也尚未运行。

失败不是“方法普遍更差”，而是 tail risk

旧 C/D selector 在 99 题上的中位 MSE 和 10% trimmed mean MSE 反而更好，但少数大尺度任务把全量 mean MSE 拉高约十倍。去掉最差 3 题后，C/D mean MASE 也会优于无 Toto 的 TimesFM baseline。这说明应优化 override risk，而不是简单删除 Statistical 或 Toto。

15. 推荐下一步

优先顺序按“先恢复可解释实验，再增加复杂度”排列。

1 · 恢复五模型运行边界

为 Moirai、Toto、Granite 建立稳定 worker env；逐模型做 immutable checkpoint smoke；把版本、device、latency 和 revision 记录为 artifact。

2 · 重跑 Train-only R1/R2/R3

仍只看 80 Train。若 Child 同时改善 mean sMAE、mean sRMSE、P90/P95 且不增加 clipped tasks，再打开一次 20 Dev gate。

3 · 让 A 与 B 真正耦合

不仅把危险方法筛掉，还要让 profile 影响 TSFM/Combined eligibility、portfolio size、correction budget 和 baseline identity。

4 · 集成复核后再冻结并运行 Retrieval

两阶段与 evolution 代码已经存在。先接入真实、已接受的 Numerical/Morphology provider 并冻结完整 run manifest，再在完全不读取 Public Regression 的前提下运行一次 Train/Dev。

停止规则：在 80 Train/20 Dev 没有稳定提升前，不再看 99 Public Test；没有新的 sealed labels，就只把 99 题称为 regression test，不声称新的 generalization。
