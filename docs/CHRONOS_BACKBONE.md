# Chronos-Bolt Backbone

The default numerical backbone is Amazon Chronos-Bolt Small using the official
`chronos-forecasting` package and the `amazon/chronos-bolt-small` checkpoint.

Official references:

- <https://github.com/amazon-science/chronos-forecasting>
- <https://huggingface.co/amazon/chronos-bolt-small>
- <https://openreview.net/forum?id=gerNCVqqtR>

## Installation

```bash
pip install -e '.[chronos]'
```

The runtime and checkpoint are loaded lazily when the first task requests a baseline.
For a cached/offline run:

```bash
drcik-agent run-sample \
  --sample-dir external/Dr-CiK/sample \
  --backbone chronos \
  --chronos-cache-dir /path/to/model-cache \
  --chronos-local-files-only
```

## Adapter behavior

```text
BaseChronosPipeline.from_pretrained(model_id)
    -> predict_quantiles(history, prediction_length, [0.1, 0.5, 0.9])
    -> median forecast becomes immutable y_baseline
```

The adapter truncates overly long histories to the configured `max_context`. Chronos-Bolt
supports horizons longer than its native prediction block through recursive quantile
forecasting; this project additionally enforces a configurable `max_horizon` safety limit.

Defaults:

```text
model_id = amazon/chronos-bolt-small
device_map = cpu
max_context = 2048
max_horizon = 1024
```

Use `--chronos-device-map mps` on supported Apple Silicon systems or
`--chronos-device-map cuda` on a CUDA host after verifying the local PyTorch runtime.

The current agent system uses the median as `y_baseline`; probabilistic trajectories are
still generated by the repository's residual uncertainty layer. A controlled next step is
to propagate Chronos quantiles directly into trajectory generation and sCRPS evaluation.

## Failure and ablation policy

Missing packages, missing checkpoints, invalid outputs, and inference failures raise
`BackboneUnavailableError`. The system never silently changes models.

```bash
# Controlled baseline ablation
--backbone statistical

# Optional alternative TSFM
--backbone timesfm

# Explicit degraded mode; method is visibly marked statistical_fallback
--backbone chronos --allow-statistical-fallback
```

Never report a run whose method begins with `statistical_fallback:` as a Chronos result.
