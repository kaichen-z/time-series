From a Method Dictionary to Safe, Task-Conditioned Forecasting

This is not a system that simply asks an LLM to guess the future. It builds an auditable forecasting pipeline: characterize the observed history, remove unsuitable methods, compare Statistical and TSFM candidates through history-only hindcasting, and evolve methods and policies under strict Train/Dev acceptance gates.

1. Research Question and Dr-CiK

Dr-CiK is an offline, context-aided time-series forecasting testbed. Each task already has history, documents, future values, and evidence annotations. Future values and evidence labels must remain hidden during inference.

Question

Input: observed values, frequency, forecast horizon, and—later—documents.

Output: a point forecast of exactly the requested horizon; probabilistic trajectories may be added later.

Goal: learn which method fits which series, then safely combine numerical methods with external context.

What this is not

  • Not live forecasting such as FutureX.
  • Not LLM weight training.
  • Not repeated tuning on Test labels.
  • Not an unguarded average of every method.

3A. Two-Stage Retrieval Self-Evolution

This is an implemented safety and evolution path, not a reported empirical win. The checked-in v000 release is an unevaluated seed. No real Retrieval 80/20 LLM evolution, post-v000 accepted release, Retrieval Public Regression evaluation, or hidden score exists as of 2026-08-28.

Result boundary: every metric elsewhere on this page belongs to earlier Numerical or contextual-baseline experiments. None is evidence for the new Retrieval Genome. Task 10 ran deterministic fake LLMs only.

A fatal Round 1 failure skips Round 2 and preserves the pure Numerical fallback. A malformed or transiently failed Round 2 preserves verified Round 1. A model cannot make a chain numerically actionable merely by setting numeric_eligible=true; trusted Python recomputes eligibility before projecting verified impacts into Decision.

Each generation creates exactly A/B/C. The default schedule screens exactly 8 entity-disjoint Train tasks, promotes at most 2, evaluates remaining Train folds, and fixes one Train winner. Only then are Parent and Child evaluated once on all 20 Dev tasks with persistence, writers, and evolvers disabled. Acceptance requires strict contextual-oracle gain without regressions in final mean sMAE/sRMSE, P90/P95, exact-quote validity, invalid/catastrophic counts, or retrieval-quality tolerances. Public Regression IDs are absent from mutation, caches, prompts, checkpoints, and acceptance.

7. What “Self-Evolution” Means Here

LevelWhat may changeArtifactAcceptance gate
Skill learningReusable Numerical, Retrieval, or Decision experienceSkill JSON or Python skillTrain outcome validation
Method evolutionAdd, repair, fork, merge, or delete forecast functionsGit-tracked methods.pyExecution, safety, Train, Dev
Policy/Genome evolutionScreening rules, selector thresholds, prompts, budgets, workflowPolicy JSON/PythonTrain winner → read-only Dev
Source evolutionAgent/Harness Python and orchestration modulesGit patchAudit → tests → Train → Dev
  1. Trusted Python runs Parent methods and records Success, NotApplicable, Crash, Invalid, and error diagnostics.
  2. A Selector LLM identifies methods worth changing; high error alone is not automatic deletion.
  3. A Coder LLM proposes typed operations such as repair or fork.
  4. AST and identity gates reject fake repairs—for example, a function still named SARIMA that only repeats the final value.
  5. Children are screened cheaply, then compared on full Train and read-only Dev.
  6. Only accepted Children become a new Git generation.

9. Phase B: Numerical Selection and Combined Forecasting

Given an Active Dictionary, Phase B chooses a method, decides whether to combine methods, and determines when it must fall back to a strong baseline.

Central performance

Median/recent sMAE, mean MAE, and mean sRMSE.

Stability

Worst fold, MAD, bias, slope error, phase error, and explosion checks.

Executability

Successful folds, coverage, Crash/Invalid, NotApplicable, and fallback behavior.

Combined means forecast-level combination

Weighted blend:
  forecast = w × TSFM + (1 - w) × Statistical

Clipped residual correction:
  forecast = TSFM + α × clip(Statistical - TSFM)

Task-conditioned route:
  if profile matches: use Statistical
  else: use TSFM

It is not checkpoint or parameter merging. A challenger may override Toto/TimesFM only when sMAE improves, sRMSE does not regress, enough folds are won, recent/worst-fold regret is bounded, coverage is sufficient, and no explosion or catastrophic pattern appears.

13. Protected Top-k in Detail

R1

Single TSFM

A different TSFM may replace the Parent only when all historical safety gates pass.

R2

Multi-TSFM Portfolio

A conservative portfolio must be more stable than the Parent, not merely better than a weak member.

R3

Joint Residual

A safe TSFM anchor receives a small, bounded, task-conditioned Statistical residual correction.

14. Open Problems

Resolved

  • 93 executable Statistical methods rather than prompt-only descriptions.
  • Deterministic JSON/manifest/checkpoint/license binding.
  • Entity-aware Train/Dev/Test and future-label firewall.
  • NotApplicable separated from Crash/Invalid.
  • Task-conditioned dictionaries and Dr-CiK-aligned sMAE/sRMSE.
  • Parent fallback and baseline protection.

Unresolved

  • Screening still shares a large common core across tasks.
  • Historical hindcasts do not reliably predict future regime shifts.
  • Strict Combined gates activate rarely; relaxed gates can be dangerous.
  • Decision-only slightly outperformed Full on the latest 99 tasks.
  • The 99-task Public Test is consumed and cannot select future versions.
  • The real Numerical/Morphology assumption provider is not yet wired to the Retrieval CLI, and the formal Retrieval 80/20 experiment has not run.
The latest evidence points to an A→B coupling problem. The candidate pool is rich enough. The next improvement should make task profiles alter eligibility, combination budgets, and baseline protection without introducing unsafe overrides.

15. Recommended Next Steps

1 · Keep Safe-Anchor as the regression champion

Protected Top-k passed Dev but did not beat Safe-Anchor/Toto on the primary 99-task mean metrics.

2 · Improve A→B coupling on Train only

Use profiles to change TSFM/Combined eligibility, portfolio size, correction budgets, and anchor identity.

3 · Add explicit tail-risk constraints

Require improvement in mean sMAE, mean sRMSE, P90/P95, and worst-fold regret before opening Dev.

4 · Freeze and run Retrieval only after integration review

The two-stage and evolution code exists. Integrate the real accepted Numerical/Morphology provider, freeze the full run manifest, then run Train/Dev once without consulting Public Regression.

Stopping rule: do not use the 99 Public Regression tasks to tune another Child. Search on 80 Train, open 20 Dev only for a final acceptance decision, and use official hidden labels only through the benchmark evaluator.
