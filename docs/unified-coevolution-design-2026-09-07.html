01A / 逐步 I/O

上一段的 Output，就是下一段的 Input

下面五段都使用同一套阅读顺序：Parent 输入 → LLM prompt → 严格 JSON → Host 验证/执行 → 冻结 artifact → 下一段输入。 紫色是 LLM 可提议内容，红色是 Host 永远不能交给 LLM 的权限。

Dictionary输出可信方法、状态、适用条件和 runtime 身份。
Numerical读取 Dictionary；输出已执行 forecasts 和可证伪 assumptions。
Retrieval读取 assumptions；输出逐条核验的 evidence card。
Decision读取 forecasts + evidence；输出已执行候选中的最终选择。
Bundle Co-evolve读取完整端到端结果；接受一个新 Bundle 或精确回滚。

一条完整示例：周期性零售序列

这是 schema 级示例，用来说明数据怎样传递，不是一次真实实验成绩。

1 · Dictionaryseasonal_naive 被标为 periodic specialist；Toto 保留为 accepted safe supply。
2 · NumericalLLM 提议 Toto 与 seasonal_naive 的 route；Host 从 Train OOF 拟合 periodicity threshold。
3 · RetrievalNumerical assumption 进入 R2；检索只返回带 exact quote、window 和 stance 的证据链。
4 · DecisionDecision 只能在 Toto forecast 与已经 materialize 的 route forecast 中选择，不能写新数值。
5 · Bundle完整系统在 Train/Dev 同时满足 sMAE、sRMSE 与 tail gates 才成为下一代 Parent。
两个不同层次：单题 inference 产生 forecast/evidence/decision；self-evolve 用很多 Train 任务比较 Parent 和 Children， 决定下一代应保存哪个 prompt、policy、recipe 或 Skill。

DictionarySupplyRelease → Numerical Parent Input
Dictionary 到底保存什么？

Python repo 是执行真相；release 是身份和审计真相。

  • 函数实现继续存放在 Git 追踪的 methods.py。
  • TSFM checkpoint、adapter、license 和 runtime identity 由 Host 固定。
  • Combined 保存结构化 parent/operator，不保存任意执行代码。
  • Screening 保存方法状态和由 TaskProfile 匹配的适用条件。
  • DictionarySupplyRelease 对所有源文件、inventory、规则和验收证据做统一哈希。
为什么不把 Dictionary 当作每轮第四个坐标？
Dictionary 一改，所有候选身份、forecast cache 和 Numerical registry 都可能失效。如果在 N/R/D 中间悄悄修改， Child 的收益无法归因，旧预测还可能被错误复用。因此它是一整个外层 supply epoch；新的 supply 会开启新的内层 lineage。
TSFM 在这里能改什么？
不训练或相加模型参数。允许进化的是经过审核的 invocation、history-only preprocessing、适用规则和 Combined 结构。 checkpoint、adapter、许可证和模型版本不可由 LLM 替换。
03 / NUMERICAL

Numerical coordinate：从目录到可比较预测

它不再重写 Dictionary 源码，而是在冻结供给上决定当前任务运行谁、如何组合、在哪个 horizon 使用谁，以及依赖哪些假设。

1

TaskProfile

周期、趋势、间歇性、regime、长度和 horizon。

2

Active Dictionary

按当前任务 morphology 实例化候选子集。

3

Materialize once

Statistical/TSFM leaf 只执行一次，Combined 只引用成功 leaves。

4

Rolling hindcast

只用历史窗口构造 sMAE/sRMSE、coverage 和 tail 证据。

LLM 提出结构

select / route / horizon_route / weighted / median / bounded_overlay

它选择 parent、结构和封闭的 assumption 条件，不填写可以直接授权收益的数值。

Host 拟合数值

threshold、weight、horizon 切点和 overlay cap 由 Python 在 Train OOF 上拟合。LLM 看不到 truth、Dev 或 Public 残差。

安全锚点

Toto 是初始 fallback，而不是永久赢家。非 Toto TSFM、Statistical 或 Combined 通过相同门槛即可成为新 Champion。

Assumptions

每个可能进入 Decision 的候选绑定多个可证伪 assumptions及 failure conditions；未进入 Decision 的试跑方法无需逐个生成。

04 / RETRIEVAL

Retrieval coordinate：为候选假设找证据

Retrieval 不知道哪一个 forecast 在真实未来上更准。它只看到清洗后的任务、文档、候选 assumptions，以及需要补足的证据缺口。

RETRIEVAL SELF-EVOLVE · 一代的真实接口

进化的是 Genome、两轮 Prompt、预算、策略与 Skills，不是 evidence 本身

A / B / C 三个互斥坐标
1 · Parent InputAccepted Retrieval Parent

完整 Genome、Skill history、Numerical assumptions、清洗后的历史任务与 Train-only Retrieval 诊断。

2 · LLM Prompt一次只改 A / B / C

A 改 Round 1；B 改 verification budgets/rules；C 改 Round 2。Prompt 带允许字段和 Parent，不带 truth/Dev/Public。

3 · LLM Output完整 Retrieval Genome

Child 必须返回严格、完整、可重放的 Genome JSON；自由字段、越权字段或未知 Skill ID 整体拒绝。

4 · Host Actions冻结并真实执行

Host 验证 ownership，冻结 Genome/Skills；逐题运行 R1→D0→R2→Verify，再做 Train 筛选与只读 Dev gate。

5 · Release OutputRetrieval Release + Cards

接受后发布绑定 Genome/Skills/验证器的 release；单题只产出经过验证的 FinalRetrievalCard。

6 · Next Input给 Decision

只传 verified chains、counterevidence、missing information、assumption bindings 与 provenance。

单题执行：Two-stage Retrieval

固定一个 Retrieval Child，在一条任务上怎样产生经过 Host 验证的 evidence。

INFERENCE
R1

Assumption-blind Search

只看清洗后的任务与文档，不先告诉它 Numerical 偏爱哪个候选。

D0

Provisional Decision

读取合法 R1 结果，最多产生一个清洗后的高优先级 evidence gap。

R2

Targeted Retrieval

只围绕这个 gap 和关联 assumption IDs 定向补证据。

V

Host Verify & Merge

逐条核对 document、quote、target、window、stance 和 assumption binding。

这不是 self-evolve。 它只是一个冻结 Retrieval Child 在一条任务上的执行流程；不会在执行过程中修改 Genome、Prompt 或 Skills。 Round 2 失败时，合法 Round 1 仍会保留。

05 / DECISION

Decision coordinate：只在真实执行结果中选择

Decision 把历史回测、候选 assumptions 与经过验证的外部证据合并，但没有权限生成一条新的数值轨迹。

DECISION SELF-EVOLVE · 一代的真实接口

进化选择规则；运行时只能选择已经执行并被 Host 认证的 forecast

Prompt / Skills / Evidence policy
1 · Parent InputDecision Parent + 两份上游产物

当前 Decision policy/Skills，加 NumericalForecastPackage 和 FinalRetrievalCard。

2 · LLM Prompt封闭选择问题

Host 给候选 ID、historical default、assumptions、已验证 chains/impacts、prior decisions；不给 truth 或造新预测的接口。

3 · LLM Output严格 Decision JSON

只能返回 selected candidate、supporting documents、rationale、是否补检索、gaps、used skills。

4 · Host Actions重新认证并 fallback

检查候选已执行、citation 属于 exact verified chain、stance/assumption 支持该 override；任何失败回到 historical best。

5 · Release OutputDecisionTrace / Policy Release

单题输出选中候选和证据链；跨代 Child 仅在 Train/Dev gate 后更新 Decision policy release。

6 · Next Input给 Bundle evaluator

传最终已 materialize forecast、选择 trace、fallback、全部组件指纹与执行审计。

LLM 可以 evolve

  • decision_prompt 与经过验证的 Decision Skills。
  • enable_evidence_adjustments、max_evidence_adjustments。
  • decision_aggregation：last 或 majority 等封闭选项。

Host 固定，不能 evolve

  • 候选 forecast 数值、candidate IDs、historical fallback。
  • Retrieval verifier、chain/quote/stance/assumption 授权关系。
  • sMAE/sRMSE、split、acceptance、ownership 与 fingerprint gate。
DecisionTrace → Bundle Evaluation Input

允许

  • 从已 materialize 的候选中选一个。
  • 选择已经 materialize 且获准的 ensemble。
  • 请求一个有类型、有限范围的更多检索 gap。
  • 在 evidence 不足时保持 safe anchor。

禁止

  • 凭空生成 forecast vector。
  • 引用未验证 document 或错误 stance。
  • 让 supporting evidence 授权相反 candidate。
  • 读取未来 truth、Dev residual 或 Public score。
Decision 同样 self-evolve。 可变部分是 prompt、Decision Skills、evidence-use policy 和 aggregation policy； accepted Retrieval release 是 Decision 进化的前置条件。
06 / 反馈

为什么它确实是 co-evolve

单向执行链之外，还存在一条严格限制的 Train-only 回路：Retrieval 和 Decision 对 assumptions 的处理结果，会变成下一轮 Numerical 的结构证据。

Cycle 1 · N

提出候选与 assumptions

候选结构进入 Retrieval，而不是 Train truth。

Cycle 1 · R/D

验证或拒绝 assumptions

记录 stance、证据质量和最终 action。

Cycle 2 · N

读取清洗后的结构反馈

知道哪类结构/条件值得继续，而不是重新盲猜。

可以反馈绝不反馈
candidate family、recipe kind、parent familiestask ID、future truth、原始 forecast vector
assumption condition、evidence stance、action outcome数值 threshold/weight、自由文本 rationale
不可用或未验证的封闭状态Dev 指标、Public record、benchmark role

若没有 accepted non-seed Retrieval trace，下一轮 Numerical 得到明确的 empty/unavailable projection，绝不伪造“Retrieval 支持”。

07 / 整体

完整系统本身也要 Co-evolve

坐标内部通过不代表系统通过。最外层以完整 UnifiedCoEvolutionBundle 为 Parent， 每次把一个坐标 Child 与其余冻结坐标重新组装，再运行端到端 Numerical → Retrieval → Decision 才做最终接受。

GLOBAL BUNDLE CO-EVOLVE · 一代的真实接口

没有一个可随意改全系统的“总 Agent”；Host 只调度一个坐标的完整 self-evolve

one coordinate per global step
1 · Parent InputWhole-system Bundle Parent

精确绑定 Dictionary、Numerical、Retrieval、Decision releases，以及 split/runtime/verifier/metric identities。

2 · LLM Prompt仅调用被选坐标的 proposer

Host 根据清洗后的端到端归因选 weakest coordinate，再把该坐标自己的合法 prompt 发给 LLM；不存在 unrestricted meta prompt。

3 · LLM Output一个 coordinate-owned proposal

输出仍遵守该坐标自己的 operations / recipes / Genome / Decision schema；不能一次修改两个 releases。

4 · Host Actions重组完整 Bundle Child

其余三坐标保持 exact Parent；运行端到端预测，比较 sMAE/sRMSE、coverage、tail、crash/invalid 和 anchor regret。

5 · Release OutputAccept Child or exact rollback

只有完整系统通过 Train 与只读 Dev gate 才发布新 UnifiedCoEvolutionBundle；否则返回 byte-identical Parent。

6 · Next Input下一代 Parent

新 Bundle 的端到端 attribution 决定下一次可能访问哪个坐标；Public-99 不进入这个回路。

LLM 可以 evolve

  • 只进化当前被调度坐标中明确开放的字段。
  • Dictionary 可改代码/供给规则；Numerical 可改 recipe；Retrieval/Decision 可改各自 prompts、policies、Skills。
  • 下一 global step 可以改另一个坐标，因此多个完整 loop 会随代际协同。

Host 固定，不能 evolve

  • weakest-coordinate scheduler、一次一坐标 ownership 与 exact-parent 规则。
  • verification、metrics、Train/Dev/Public split、runtime/source fingerprints。
  • 端到端 acceptance gate；局部得分或 LLM 自评没有发布权限。
Accepted Bundle → 下一代 Bundle Parent

G1

G2

错误归因

G3

可能的最弱坐标Host 可观察的聚合信号下一步

Retrievalgap 未覆盖、citation/quote verification failure进化 Genome、query、budget、Skills。

Global Child 构造

被选坐标替换为 Child，其余三个坐标保持 exact Parent。若改变 Dictionary，必须重新构建 Numerical registry 与 forecast cache，禁止复用旧 supply 的预测。

Global acceptance

局部指标只能做筛选；最终必须由完整系统的 sMAE、sRMSE、coverage、tail、crash/invalid 与 anchor regret 共同决定。

1

一次只改变一个坐标

这不等于四个 Agent 互不影响；它保证每个完整 Bundle 改善可以归因，同时允许下一代根据全局结果切换目标坐标。

08 / 协议

80 / 20 / 99 的边界

新框架采用最新 Train-Dev 协议：8 和 32 都是 Train 内的早筛；Train-80 使用按 entity 分组的五折 OOF；Dev-20 只接受；Public-99 只报告。

Screen-8

低成本排除结构非法、明显失效或严重退化的 Children。

Screen-32

扩大任务覆盖，保留有限 finalist；行为相同的参数版本由 Host 保留代表，而不是让 hash 随机决定。

Train-80 · 5-fold OOF

每次用四折拟合 routing/weight，在剩余一折评分；共享 entity 的任务始终位于同一折。

Dev-20 · read-only

固定 Train finalist 与 Parent 做一次接受比较；不再修改 threshold、prompt、Skills 或下一轮反馈。

Public-99 · frozen only

完整 bundle 冻结后由独立命令打开一次；结果不能回流。

sMAE尺度归一化的绝对误差主要反映典型幅度偏差
sRMSE尺度归一化的平方误差对大误差与尾部更敏感
Pareto gate两者分别约束joint score 只排序，不单独授权
T

尾部与稳定性

同时检查 coverage、crash/invalid、raw/capped P90/P95、clipping、catastrophic、oracle regret 和 safe-anchor regret。

P

Parent 精确保留

任何 Child 失败或越权，都返回 byte-identical Parent；不能用“部分更新”掩盖失败。
