Auditable Self-Evolving Cross-Modal Forecasting
From "evidence extraction" to "document-anchored correction" (CorDP)

On top of a numerical foundation model (Toto), we modify the forecast with document evidence through an evolvable, auditable adjustment layer. The core idea: the cross-modal interaction policy — how text reshapes a numerical forecast — is discovered as readable code by evolution, not hand-designed.

Dr-CiK 80 / 20 / 99 base = Toto-2.0-22m (strong) perception = haiku (cached) policy = evolved pure code

Five Highlights

⓪ On sparse data, "judging your own overfitting" matters more than "evolving a stronger policy"

Today's whole honesty chain (held-out → k-fold CV → grouped / leave-domain-out CV → significance gate → meta-validation) shows every "evolved complex policy" collapses under honest evaluation (whole-99 −1.2% / 28 reg). The real capability is not a stronger policy but the system being able to tell whether a gain is real vs overfit-in-noise. That self-assessment is exactly what keeps it from self-deceiving on sparse data, makes it converge to do-no-harm, and lets it precisely localize the true residual value (the text-side recall lever, +2.50% at zero regression). On small data, a trustworthy evaluator > a stronger optimizer.

① The text→math principle

Text supplies the structure of the math operation plus a pointer to where the number lives — it never invents the number. Magnitudes come only from an "explicit quote / a data analog"; when neither exists → abstain. Realized as per-parameter grounding tags.

② Anchoring breaks the magnitude wall

Replace "ask for the magnitude in the abstract (→unknown)" with "show the LLM the base numbers and let it correct them" → magnitude becomes usable. task_163: multiplier 0.93 vs oracle 0.935.

③ An auditable, evolved symbolic policy

The interaction policy is readable code (primitives + parameters), discovered by evolution, with an invariant kernel guaranteeing bounded + grounded output — not a black-box LLM, not a trained model. Readable / traceable / provably safe.

④ Precision-first on sparse, adversarial data

Grounding + abstain → zero-regression net-positive on sparse, low-signal-density, adversarial data — exactly the regime where "modify everything" (goes negative) and "data-hungry" (overfits) fail.

Positioning vs the field: NEXUS (2605.14389) has the LLM output numbers to beat a TSFM, but compares only against TimesFM + CoT (no statistical methods) and wins by ~7%; LAFP (2607.24892) tests strong and weak baselines honestly — only 2-6% on strong-baseline CiK, 60% on weaker. The pattern: big "text wins" come from weak baselines / omitted statistical methods / benchmarks designed so context is essential. We do not bet on "LLM replaces a strong TSFM" — we bet on "safe sparse gains on top of a strong TSFM", and hit zero-regression in the strong-baseline + adversarial-sparse regime others avoid.

0In one sentence

Pure numerical is capped (champion ≈ Toto), and the "select-a-candidate" paradigm is capped too. Documents carry real signal (oracle diagnosis: on 12/20 dev tasks the best scaling cuts error ~33%), but under the old "make retrieval emit {direction, magnitude}" paradigm the magnitude is always unknown. The pivot: stop extracting an abstract magnitude; instead give the LLM the Toto base numbers + documents and let it output a "correction multiplier" anchored on concrete values (CorDP) — the magnitude wall breaks.

1The pivot: why CorDP

Why the old (extraction) paradigm is capped

Retrieval reads documents → structured {direction, magnitude}. Given the numeric context the LLM turns conservative and returns unknown for magnitude; pure data can't estimate an event's magnitude either (short history has no precedent). Variants (regime-fill, analog scaler, self-consistency sampling) all regress under LOO.

= the failure mode the literature names: "reasoning right, numerical application wrong."

The new (CorDP correction) paradigm

Show the LLM the base forecast numbers + documents, and have it output a multiplier per sub-window. Magnitude is anchored on concrete Toto values → unknown becomes a usable number.

Literature: CorDP (2508.09904) corrects rather than extracts, +50%; LAFP (2607.24892) has the LLM only rank TSFM traces, 2-6% on strong CiK / up to 60% on weaker Time-MMD.

CorDPAdjust's precision gates (all evolvable) — the "hand-set in the literature, evolved by us" contribution

  • conf_min: abstain (leave Toto alone) when the LLM's self-reported confidence is below this
  • wfrac_max: reject a correction spanning more than this fraction of the horizon (a whole-horizon rescale is the base model's job and always misfires)
  • mult_lo / mult_hi: clamp the multiplier (the kernel adds a further ±50% bound)
  • shrink: partial trust eff = 1 + shrink·(m−1)

In the literature the thresholds of CorDP / IC-DP / LAFP are all hand-set; evolving them (and the "which primitive" orchestration) into readable code is new.

4Evolution & accumulation

Evolution algorithm · parent → child (μ+λ)

It is generational parent→child evolution. Population = a set of controllers; each generation:

  1. Rank by (fitness, −steps) — parsimony tie-break (shorter wins, more auditable)
  2. parents = top elite (μ); elites survive into the next generation
  3. Fill up to pop_size: 50% crossover two parents, 50% copy one parent, then mutate (insert / delete / reorder / edit-param)
  4. pop = children → next generation; track best throughout
parents (elite μ) ──┬─► elites survive ──────┐
               ├─ 50% crossover(p₁,p₂) ─► mutate ─►├─► children = next pop
               └─ 50% copy(p) ─────────► mutate ─►┘

Seeds = SEED_CONTROLLERS (incl. CORDP_CONTROLLER) + champions accumulated in skill memory. Fitness = CVaR downside (mean + β·worst-tail mean) / windowed ROI, penalizing regressions.

All three loops are parent→child: B (controller) = full (μ+λ) with crossover + elitism; A (retrieval weights) / N (numerical-combo weights) = lighter ES (top-k parents → Gaussian-mutated children; N adds CV / held-out + L1 selection).

Skill memory (accumulation)

Store evolved good controllers as JSON, deduplicate, reload as seeds next run (Voyager / AlphaEvolve program-database style). Note: it accumulates "arrangements of primitives", not new atomic primitives — those are written by a human / LLM-design.

Evolution results (2026-09-19)

  • Prerequisite fixed: under a whole-horizon + CVaR objective, evolution collapses to identity (windowed gains are diluted); with a ROI (event-window) metric, evolution finds a non-trivial controller (no longer "do nothing").
  • What it finds is a precision/recall frontier: on train ROI, conf≥0.9 = 6 wins / 0 reg (conservative, zero-regression end) → conf≥0.6 = 21 wins / 13 reg (aggressive end). Evolution slides along this frontier via the downside weight β — β=2 to the zero-regression end, mean to the aggressive end.
  • The aggressive gate conf≥0.68 that evolution (mean) chose also generalizes on test99: +2.5% / +4.6%, 28 wins / 2 reg (higher aggregate than the hand-set conservative gate's 17 wins / 0 reg, but 2 regressions).
  • Proper protocol run (train search → dev select → test confirm): the gate is per-task → train-internal LOO ≈ in-sample, so dev is the real held-out selector; but dev is too small (12 ROI / 4 touched) to select — the gate it picks scores poorly on dev/train yet strongly on test, i.e. data-driven gate selection is unreliable on Dr-CiK (again the sparse / data-limited ceiling).

Diagnosis: the evolution objective must be windowed

Under a whole-horizon + CVaR objective, evolution converges to identity (no change, zero improvement, zero regression) — the in-window gains are diluted over the whole horizon and can't overcome the CVaR downside penalty. This is exactly the CiK / RCRPS lesson: score by region of interest. Fixed by switching fitness to windowed CRPS / MAE.

Harness framing: the whole system is a self-evolving, auditable forecasting harness (strong base + gated grounded correction + invariant kernel). The system (CorDP / evolution / three-loop CCEA) is the auditable instantiation of the theory. → theory + system + experiment, three legs.

6Direct vs step-by-step (residual propagation experiment)

Should the base forecast the whole horizon at once (direct) or step-by-step (autoregressive)? The only real advantage of step-by-step is letting a correction propagate forward (a recovery curve after an outage, a permanent level shift); the cost is error accumulation + drift. Rather than real AR, we test "propagation" symbolically via ResidualAdjust shapes (step=persistent, decay=recovery), avoiding AR drift.

So: keep the base direct; step-by-step AR does not help (its propagation advantage is actively harmful here); and the wfrac gate that "rejects global/persistent corrections" is thereby vindicated. The few genuinely propagating events are captured symbolically via the decay shape.

8The core thesis: how to use text to do math

text→math = a product of three things, don't conflate them: ① structure (which variable / direction / window / shape — text is good at this, essentially free) × ② magnitude (the real hard part) × ③ trust (when to stay silent).

Text supplies the *structure* of the math operation and a *pointer to where the number comes from*; it never invents the number. The number comes only from an "explicit quote" or a "data analog"; when neither exists, the only correct operation is "do nothing".

The nature of the magnitude wall: when the number is in neither the document (stated) nor the data (analog), inventing it is necessarily wrong — the gate (confidence + locality) exists to detect this and abstain. ResidualAdjust's grounding tags bake this principle into every parameter.

The pattern (most useful for positioning): text gain ≈ f(baseline strength, whether statistical methods are compared, whether the benchmark is designed for text). Papers reporting "big LLM wins" mostly took a shortcut — weak baselines (NEXUS/Beyond-Naive/MoTime), omitted statistical methods (NEXUS), or a context-essential benchmark (CiK). The honest broad comparison (LAFP on CiK) is only 2-6%. We sit in the "strong-baseline Dr-CiK + full numerical suite + zero regression" bracket — honest, and avoided by others — not betting on LLM replacing a strong TSFM, but on safe sparse gains on top of it.

Contribution positioning: neurosymbolic + hierarchical self-evolution — the LLM does only the irreducible perception (read docs → cached structured corrections), evolved pure code does all the policy, and the output is auditable (grounding coverage, a bounded certificate, printed rules). The literature hand-designs this interaction policy; nobody self-evolves it, and nobody produces auditable interaction rules — that is this work's open niche.
